# Controller observation to local-owner seam

MW3-080 supplies explicit four-slot ownership and stale binding checks. The
selected SDK's raw provider and input-system policies are measured by 084/085;
086 repairs held input between device addition and SDK discovery in an opt-in
private profile. These components have not yet been composed into the owner's
chosen local-player routes. SDK user numbers, enumeration position, a neutral
fallback reading and vendor/product equality cannot establish player ownership.

MW3-087 isolates that composition before physical task 083. Its public C++20
component consumes bounded typed observations, assigns fresh connection tokens,
normalizes original host controls and delegates explicit reservation/attachment
and frame publication to the unchanged MW3-080 API. Removed devices neutralize
their routes while preserving owner reservations. Reused backend IDs, backend
restart, late observations and old ownership bindings must not revive input.
Unknown controls and partial/invalid publications fail diagnostically. Tokens
are stale-event guards, not authentication or persistent device identities.

A separate SDK-facing diagnostic loads the actual repaired raw provider through
its existing interfaces and passes four distinguishable original process-local
virtual devices into the public component. It preserves every current SDK,
profile, fixture and shared model interface; captures exact loaded libraries
and source/binary/configuration identities; and exercises explicit joins in all
24 device orders. Original host button identities must be mapped explicitly
from SDK values, without adopting Xbox bits as a guest or host ABI by accident.
The established SDK-facing C++23 adapter convention does not change the C++20
public component requirement.

The raw-provider seam does not implement the separate SDK input-system's UI
blocking/shared/fallback policies. Physical integration 083 must choose and
validate that policy alongside ownership, physical mappings and device lifetime.
Four physical controllers, pre-existing controls held before SDL first open,
mapping reloads, independent hardware, guest ABI/services and title input remain
unverified. Host composition cannot complete 083, 012, console split-screen or
four-player Survival. Broader shared-interface or SDK changes need their own
scope before implementation.

This planning change only creates 087 and adds its dependency to unassigned
083. It does not claim either task or modify runtime/SDK code. Claim 087 through
task-admin after this plan merges and its four completed dependencies are
verified remotely. The main allocation/audio lane remains separate.
