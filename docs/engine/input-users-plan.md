# Input-system routing prerequisite

MW3-084 tested the selected raw SDL3 provider. It did not instantiate the SDK
input-system module, assign four SDK users, verify its packet/blocking behavior
or connect the explicit MW3-080 ownership model. Those are separate contracts.
MW3-085 makes that bounded investigation a prerequisite of physical backend 083.

The selected `IInputSystem` source documents four SDK users, a neutral user-0
fallback and an optional shared-pad setting. Its assignment implementation
retains existing device ordinals and allocates available ones to new devices.
These are source observations, not four-controller or title execution evidence.
Raw-device success must not be promoted to proof that this layer preserves
independent local players, or that its implicit assignment matches explicit
owner reservations.

The child owns only `tests/host_platform/input_users`,
`tools/test_input_users.py` and `docs/engine/input-users.md`. It loads the real
private input-system/provider modules and original virtual devices. It changes
no SDK source/profile, accepted model, physical backend, shared test namespace,
guest allowlist or generated code. Allocation 046 and profile-storage 081 keep
their reserved paths, processes and private resources.

Use the established isolated SDK-facing adapter convention with actual owned
host services and bounded event dispatch. Keep public evidence guards game-free
and standard-library-only; public core stays C++20. Device-order, packet,
hotplug, nested UI block, fallback and shared-pad cases must report actual
results and library identities. Expected SDK policies are not a retail MW3
controller specification. A demonstrated defect requires a separately agreed
repair before any SDK or shared-interface change.

Four physical devices and actual guest input remain required follow-up evidence
for 083/012. No physical player, Xbox account, game address, console split-screen
behavior or four-player Survival extension is supplied by this planning split.
